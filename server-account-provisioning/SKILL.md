---
name: server-account-provisioning
description: 查询实验室服务器账号所在主机，或为给定学号、特殊用户名创建普通 Linux 账号。适用于用户配置的 Linux 服务器上的账号定位、冲突确认、开户验收和操作记录。
---

按需读取 [服务器与本地索引](references/servers.md) 和 [开户与验收](references/provisioning.md)。

1. 区分查询、开户和用户另外要求的账号操作。12 位学号规范为 `s<学号>`，已带 `s` 的学生账号保持原样。明确给出的特殊用户名保留原值并校验格式。批量输入去重前先报告重复项并等待修正。开户必须有明确的目标服务器。
2. 先找本地索引，再按精确用户名查本地开户或查询记录。普通查询可直接返回历史位置、日期和来源。无本地命中或用户要求查当前状态时，逐台查询纳管服务器，首个命中后继续查剩余主机。开户前应核验目标并做跨主机查重。对用户要求的实时查询或写操作，优先使用本次指定的连接身份，其次使用 [服务器连接配置](references/servers.md) 中的默认管理员用户名和已配置认证。缺少配置或认证失败时，说明缺项并停止相应服务器上的操作，仍可返回已知历史结果。
3. 返回全部已知命中，并区分实时、历史、确认不存在和未验证。多台命中时，询问接下来要操作哪台，是否需要另行处理某台重复账号（包括删除），然后等待答复。仅查询时同样可以先交付结果。开户发现任何已有账号时，返回其账号和位置，询问是否继续开户及目标机。收到答复后才进入写操作。目标机有同名账号、组或路径时，显示冲突，整批停止；确认继续也不覆盖已有对象。其他主机未验证时如实告知；若查重无法完成，先交给用户决定是否仍在指定目标开户。
4. 删除属于单独请求。上述询问本身不授权删除。若用户提出删除，先核验确切主机和账号，说明该账号及数据的处理范围，明确是仅删除账号还是还需删除数据，并获得明确确认。开户脚本不提供删除能力。
5. 按开户参考执行批量预检和验收。记录逐账号结果、失败步骤、已知原因及遗留状态。依据确认的结果更新本地索引，勿把未执行或未验证写成成功。
