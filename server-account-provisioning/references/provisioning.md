# 开户与验收

在确认目标、名单和已发现冲突的处理结果后，将 `scripts/create_accounts.sh` 作为独立脚本交给目标 Linux 服务器。先审阅并核对传输后的文件。命令形态为 `sudo -n bash ./create_accounts.sh --check lab-node-a s000000000001 demo2026`。用户名须匹配 `[a-z_][a-z0-9_-]{0,31}`；学生账号按 `s` 加 12 位数字规范。预检通过后以相同名单运行 `--apply`，脚本会在锁内重做预检。仅在用户明确要求开户并满足冲突确认后执行 `--apply`。

`--apply` 从标准输入读取一行统一初始密码。使用部署方配置的受保护来源，例如工作区 `.server-account-local/initial-password`（目录 700、文件 600），经 SSH 标准输入传递，关闭命令追踪。开工前确认秘密来源可用。密码不得出现在命令参数、环境变量、聊天回复、报告、可分享 skill 包或工具输出。学生首次登录由本人在终端改密，按用户认可的渠道提供初始密码。

- 账号登记为 `/home/<账号>`，Shell 为 `/bin/bash`，只有同名主组。`/home/<账号>` 是 root 所有的软链接，指向 `/data/private/<账号>/home`。
- 数据根目录 root:root、755。home、workspace、conda、envs、pkgs、`.ssh` 和 `.conda` 归用户及同名组、700。`.condarc` 为 600，写入该用户的环境和包缓存目录。workspace、`.conda/envs` 和 `.conda/pkgs` 软链接分别指向相应数据目录。
- 预检目标机身份、`/data` 独立挂载和可写、父目录权限、命令可用性，以及账号、组、路径冲突（含悬空软链接）。已有账号与已有数据不在此脚本的操作范围。
- 创建时保持密码锁定且账号暂设过期。验收用户身份、目录、权限、链接和 `.condarc`，以实际用户身份验证四处可写且设备号与 `/data` 一致，清理验证文件。设置初始密码后验证已设置密码和首次改密标志，然后解除临时到期限制。
- 检查 SSH 的实际对外配置，涉及 `Match` 时使用目标用户和有代表性的来源条件。把服务端配置检查与真实 SSH 登录分开报告。若已有可用 Conda，可用用户身份读取配置；没有则标明未执行此项。开户只配置路径，学生本人完成首次登录与改密。

将本次报告保存在工作区，逐账号记录成功、失败或尚未开始。成功项记录 UID/GID、登录命令和实际验收结果。失败项写清步骤、退出信息和可确认原因，说明账号、密码启用和目录状态。操作中断或 SSH 断开时用只读方式回查，结果未知时明确写未知。保留半成品、停止余下账号，恢复或清理应针对确认后的状态单独处理。
